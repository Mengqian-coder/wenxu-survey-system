## 3 重新运行测试

### 3.1 准备环境

先按[项目启动说明](../README.md)安装 Python 依赖和 MongoDB Server。前端单测还需要 Node.js 和前端依赖，浏览器测试还需要 Microsoft Edge。

以下命令均在 `01_代码` 目录的 PowerShell 中执行。数据库集成与浏览器测试会自行启动独立副本集和测试服务，不需要先启动日常使用的项目。找不到 MongoDB 程序时，将 `MONGOD_BIN` 设置为实际 `mongod.exe` 路径。

### 3.2 常规回归

只运行后端：

```powershell
& .\backend\.venv\Scripts\python.exe -B .\backend\scripts\run_tests.py --suite backend
```

运行后端、前端单测和浏览器全部套件：

```powershell
npm.cmd --prefix frontend ci
& .\backend\.venv\Scripts\python.exe -B .\backend\scripts\run_tests.py --suite all
```

需要单独运行前端单测或浏览器时，将参数分别改为 `--suite frontend` 或 `--suite e2e`。关闭与提交竞争的筛选命令见[专项说明](04_关闭与提交竞争专项.md)。

### 3.3 第二阶段专项

版本、快照与权限专项：

```powershell
& .\backend\.venv\Scripts\python.exe -B .\backend\scripts\run_mechanism_evidence.py
```

校验边界与反例补测：

```powershell
& .\backend\.venv\Scripts\python.exe -B .\backend\scripts\run_validation_evidence.py
```

两项专项的完整检查范围及证据字段分别见[机制专项说明](05_版本快照与权限执行证据.md)和[校验补测说明](07_校验边界与反例补测.md)。需要归档时，可追加 `--publish <尚不存在的目录>`；只有全部通过且执行期间源码未变化，运行器才会复制并校验证据。

## 4 执行输出与证据目录

重新运行生成的文件位于 `01_代码/output`，每次使用新目录，不覆盖已有归档：

| 运行方式 | 输出目录 |
|---|---|
| 常规套件 | `output/test-runs/<运行编号>/` |
| 版本、快照与权限专项 | `output/mechanism-evidence/<运行编号>/` |
| 校验边界与反例补测 | `output/validation-evidence/<运行编号>/` |

已经随交付材料保留的证据位于本目录的 `证据` 中：

| 证据位置 | 保存内容 |
|---|---|
| [证据根目录](证据/) | 第一阶段的运行汇总、JUnit、用例明细及文件校验清单 |
| [关闭提交竞争专项](证据/关闭提交竞争专项/) | 受控时序、专项结果及回归记录 |
| [版本快照权限专项](证据/版本快照权限专项/) | 场景请求响应、数据库快照、断言、源码及证据哈希 |
| [校验补测专项](证据/校验补测专项/) | 实际容量边界、错误码、数据库状态摘要及相关回归结果 |
| [阶段验收](证据/阶段验收/) | 基础流程、管理、统计、换版和输入修复等阶段的归档记录 |

[测试运行器](../01_代码/backend/scripts/run_tests.py)和[数据库 fixture](../01_代码/backend/tests/conftest.py)不读取日常 `.env`，不连接日常开发数据库，结束后只清理自身创建的测试资源。结果按参数化展开后的执行项计数，不用文档表格行数或断言数量代替。
