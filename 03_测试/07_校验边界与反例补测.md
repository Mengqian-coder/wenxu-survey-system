# 校验边界与反例补测

本次针对完成报告中的三项证据缺口补充测试：默认 12 MiB 请求体边界、最终 BSON 文档 16 MiB 检查，以及已识别反例的状态码、错误码与数据库结果断言。使用真实应用及独立 MongoDB 副本集，实际执行 **125 项，全部通过，失败、错误、跳过均为 0**。

其中 10 项是新增容量边界测试，另 115 项为既有反例补强及相关回归。测试通过一次完成，pytest 控制台记录耗时 97.07 秒；运行器计入进程启动后的总耗时为 98.768 秒。控制台有 1 条既有 TestClient 依赖弃用提示，不属于业务失败。50 个相关源码、脚本和数据库定义文件在执行前后保持相同哈希。

## 1 默认请求体边界

保持 `max_request_bytes` 的默认 12,582,912 字节配置，使用合法注册 JSON 加尾随空白精确构造正文，避免把字段本身非法和请求体超限混为一类。每项使用独立测试库并先保存一名基准用户。

| 输入方式 | 实际正文大小 | 预期与实际结果 |
|---|---|---|
| 正常 Content-Length | 12,582,911 字节 | 201，新增用户实际保存，原有数据不变 |
| 正常 Content-Length | 12,582,912 字节 | 201，新增用户实际保存，原有数据不变 |
| 正常 Content-Length | 12,582,913 字节 | 413 REQUEST_TOO_LARGE，全部集合完整文档不变 |
| Content-Length 伪称为 1 | 12,582,913 字节 | 413 REQUEST_TOO_LARGE，全部集合完整文档不变 |
| 缺失 Content-Length | 12,582,913 字节 | 413 REQUEST_TOO_LARGE，全部集合完整文档不变 |

后两项通过当前应用生命周期内的真实 ASGI 中间件链，以原生 `receive` 分块输入，避免 TestClient 将生成器合并为一个块。实际消费 13 块：12 块各 1 MiB，最后一块 1 字节。该结果证明实际正文测量不会被伪小或缺失的长度声明绕过；未使用真实 TCP 网络传输。

原有缩小阈值用例保留，并为正常声明超限、伪小声明超限、非法及负数长度声明的 4 次拒绝增加错误码和完整数据库快照断言。

源码见[默认请求体边界用例](../01_代码/backend/tests/test_request_size_evidence.py)及[原请求限制用例](../01_代码/backend/tests/test_api.py)。

## 2 BSON 大小与写入前拒绝

纯边界用例使用包含中文及表情的字符串，按实际 UTF-8 和 BSON 开销构造文档，并调用未经替换的生产 `ensure_size`。

| 实际 BSON 编码大小 | 预期与实际结果 |
|---|---|
| 16,777,215 字节 | 大小检查接受 |
| 16,777,216 字节 | 大小检查接受 |
| 16,777,217 字节 | 抛出 413 DOCUMENT_TOO_LARGE |

以上合法边界只验证编码与大小检查，没有将这些文档插入 MongoDB。

另两项通过真实 HTTP 创建和修改问卷，在正常版本绑定完成后向内部快照注入膨胀，令实际最终 BSON 为 16,777,217 字节。实际请求正文分别为 245 和 163 字节。大小检查及 BSON 编码均执行生产函数，未伪造接受或拒绝结果。

两项均返回 `413 DOCUMENT_TOO_LARGE`，监测到问卷最终插入或更新的尝试次数为 0。拒绝前已在事务内发生的回执插入和题目 guard 写入完整回滚；逐文档 BSON 字节比较确认 11 个集合的持久化状态全部相同，前后摘要一致。

这两项证明防御性服务检查及回滚有效。普通输入还受请求体、字段与数组容量限制，本测试没有声称其可以自然生成 16 MiB 的合法业务文档。源码见[BSON 边界与事务用例](../01_代码/backend/tests/test_bson_size_evidence.py)。

## 3 反例断言补强

完整数据库快照按集合名、文档 ID 排序读取，比较完整文档，包括修订号、时间、引用及回执；不以记录数相等代替内容不变。适用的静态反例同时检查公开错误结构、准确状态码与业务错误码、请求前后完整数据库状态。

| 补强范围 | 代表错误与检查 |
|---|---|
| 请求大小、非法声明 | 413 REQUEST_TOO_LARGE，拒绝不写入用户或其他文档 |
| 分页、筛选、非法字段和伪造快照 | 422 INVALID_REQUEST，原内容、修订号及回执不变 |
| 同卷重复题目 | 422 DUPLICATE_QUESTION，无部分问卷或成功回执 |
| 未登录及越权、资源归属错误 | 401 AUTH_REQUIRED 或 404 NOT_FOUND，不改变资源与授权 |
| 发布冻结与归档 | 409 SURVEY_LOCKED、QUESTION_ARCHIVED、VERSION_ARCHIVED，已有内容保留 |
| 旧修订号及幂等键冲突 | 409 REVISION_CONFLICT 或 IDEMPOTENCY_KEY_REUSED，不产生新版本、回执或状态覆盖 |
| 撤权后新增使用、题库管理 | 按对应接口错误拒绝，完整数据库状态不变 |

并发操作中，另一合法请求本来可以改变数据库，因此按成功请求核对最终业务状态；题库并发用例另检查失败操作无成功回执残留。超时关闭等有约定状态变化的场景沿用其专门断言。静态资源 404、CORS 拒绝不属于业务 `error.code` 合同范围。

修改和回归来源包括[题目引用流程](../01_代码/backend/tests/test_library_flow.py)、[跨问卷统计](../01_代码/backend/tests/test_cross_survey_statistics.py)、[题库管理](../01_代码/backend/tests/test_question_banks.py)、[共享权限](../01_代码/backend/tests/test_question_sharing.py)、[管理写幂等](../01_代码/backend/tests/test_mutation_idempotency.py)及[问卷列表筛选](../01_代码/backend/tests/test_frontend_support.py)。上述结论限于本次识别和执行的用例，不表示所有输入组合已穷尽。

## 5 复现与剩余体验验证

按[项目启动说明](../README.md)准备 Python 环境及 MongoDB，在 `01_代码` 目录执行：

```powershell
& .\backend\.venv\Scripts\python.exe -B .\backend\scripts\run_validation_evidence.py
```

运行器使用测试 fixture 自行启动的独立副本集和随机库，不读取日常 `.env`，不连接业务库；结束后清理自己的子进程与测试库。找不到 MongoDB 程序时设置 `MONGOD_BIN`。每次证据写入新的 `output/validation-evidence/<运行编号>/`；可用 `--publish <尚不存在的目录>` 归档，只有全部通过且源码未变化才复制并逐文件核验。

完整人工体验仍通过[人工脚本](06_新增功能人工体验脚本.md)单独记录。M01 至 M11 尚待填写；本次补测不包含操作系统原生中文输入法组合输入或异步保存后的回焦。
