# 旧问卷显式迁移说明

实现日期：2026-10-23。

此工具将原有 `schemaVersion=1` 的嵌入题目问卷转为新版固定版本引用。旧问卷无需迁移也能继续读取、发布、填写和查看原问卷统计；需要在草稿中调整题目结构，或让旧题进入题目管理及跨问卷统计入口时，再由数据库管理员明确选择迁移。

工具不在应用启动、页面访问或测试之外自动运行。本轮开发仅在自动化测试创建的独立随机数据库中执行过迁移，没有迁移日常开发数据库。

## 迁移边界

每份问卷单独使用一个事务，建立该卷每个旧实例对应的独立题目及 v1 版本，并更新整份问卷：

- 题目归属于旧问卷所有者，`origin={kind:"legacy",surveyId,instanceId}`；首版操作为 `migrate`，内容仅保存题型、题干、说明、选项、校验限制。
- 保留原本地题目 ID、内容、是否必答、顺序和跳转规则，仅追加 `questionId/versionId/versionNo`；`schemaVersion` 变为 2，`revision` 增加 1。
- 不根据题干相同合并题目。即使两个旧问卷原来使用相同文字，迁移后也对应独立题目、分别统计。
- 不读取、修改或重写答卷和参与记录。答案与跳转继续通过旧本地 ID 对应，原填写凭据和提交重试仍可使用。
- 已发布、已关闭问卷也可迁移结构表示，题目内容、问卷状态、截止时间及发布/关闭时间保持原值。发布冻结规则继续有效。
- 问卷 `createdAt/updatedAt` 等业务日期保持原值，避免把结构转换显示为业务编辑；新题目和首版的 `createdAt` 记录实际迁移时间。管理修订号的递增使迁移前的旧编辑请求产生修订冲突，使用者需刷新后继续管理。

题目主档和版本、整卷引用必须一起提交；中途失败会整卷回滚，不留下半迁移的新题或版本。多个问卷之间不使用一个大事务，已完成的卷不因后续卷失败回滚。

## 执行方法

以下命令在 `01_代码` 中执行，复用 `backend/.env` 或当前环境变量中的 `MONGODB_URI/MONGODB_DATABASE/SECRET_KEY` 配置。工具不会输出连接串、密钥、答案或填写凭据，也不创建集合、修改验证器或自动创建索引。

先部署新版数据库定义，并由操作人员完成目标库备份及目标确认。查询副本集和预览均为只读操作；**只有明确传入 `--apply` 才执行写入**。

```powershell
# 默认预览整个目标库中的旧问卷
& .\backend\.venv\Scripts\python.exe .\backend\scripts\migrate_legacy_surveys.py

# 明确预览指定问卷，可多次传入 --survey-id
& .\backend\.venv\Scripts\python.exe .\backend\scripts\migrate_legacy_surveys.py --dry-run --survey-id 000000000000000000000101

# 核对预览后，只迁移这份问卷
& .\backend\.venv\Scripts\python.exe .\backend\scripts\migrate_legacy_surveys.py --apply --survey-id 000000000000000000000101

# 分页扫描，每批最多读取 50 个 ID；本次最多处理 200 份问卷
& .\backend\.venv\Scripts\python.exe .\backend\scripts\migrate_legacy_surveys.py --dry-run --batch-size 50 --limit 200
```

示例中的 ObjectId 仅为占位，请换为预览或实际管理记录中的 ID。汇总输出包含模式、数据库名、处理/失败数量、题目数和最后处理的问卷 ID；单卷输出只含 ID、状态、题目数和修订号，不含问卷题干或答卷。

没有 `--survey-id` 时仅扫描旧卷；显式指定已迁移问卷会返回 `already_current`，指定不存在的问卷返回 `not_found`。退出码为 0 表示本次扫描正常完成，1 表示存在卷级失败，2 表示配置、预检查、参数或数据库操作失败。

## 失败、并发与重跑

- 扫描使用按 `_id` 递增的游标。需要分次处理时，可使用 `--after-id <上次最后处理ID>`，其含义是继续处理该 ID 之后的问卷，不包含该卷。失败的卷应按输出 ID 单独检查、处理和重跑，不能因为后续游标前进而忽略。
- 正常并发编辑会触发事务写冲突，工具最多重试整卷事务 3 次，每次重新读取问卷。新的题目身份在回滚后失效，不会覆盖并发保存的内容。
- 题目来源使用唯一索引 `(origin.surveyId,origin.instanceId)`，版本使用 `(questionId,versionNo)` 唯一索引。重复运行已完成卷不会再次建题或递增修订号。索引缺失时拒绝实际执行，需先部署正确的数据库定义。
- 同一问卷两个迁移进程竞争时，只能形成一组旧实例来源。若发现已有来源但卷仍为旧结构，工具拒绝采用这些孤立记录，不猜测归属或手工拼接半成品。
- 提交响应丢失时，只重试原事务的提交，随后通过 primary/majority 读取整卷结构和唯一旧实例来源确认。若仍不能确认，返回 `MIGRATION_RESULT_UNKNOWN`，不重新进入业务创建；保留原问卷 ID 查询或重跑，也不要手工补建题目。汇总不会把未知结果的卷当成安全续跑游标。
- 保留完整输出便于检查各卷结果。迁移是有意保存的正式题目版本，没有自动“回退为嵌入题目”操作；数据恢复依赖执行前的数据库备份。

此为离线数据库管理工具，不新增公开写接口，也不使用浏览器管理接口的 `Idempotency-Key`。它使用明确的问卷目标、整卷事务、问卷修订号和永久唯一来源保证安全重跑。

## 验证

自动化测试见 [test_legacy_migration.py](../01_代码/backend/tests/test_legacy_migration.py)，复用专属临时副本集 fixture，覆盖默认只读、同文不合题、四种题型与跳转保留、发布/关闭及答卷不变、空草稿、二次执行、并发编辑与同时迁移、故障整卷回滚、未知提交确认、不重复进入未知业务，以及迁移后草稿编辑、迁移前开始填写和提交重试。

```powershell
# 在 01_代码/backend 中执行；测试不会连接 .env 中的日常数据库
.\.venv\Scripts\python.exe -m pytest tests/test_legacy_migration.py -q
```

完整系统验收结果见本轮交付记录；迁移不代表任何历史同文题自动建立了跨问卷身份关联。
