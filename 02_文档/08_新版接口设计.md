# 问序新版接口设计草案

整理日期：2026-10-22。

依据：[业务规则定稿](06_新版业务规则.md)、[数据模型设计](07_新版数据模型设计.md)。本文保留完整目标接口设计；基础流程、管理能力及跨问卷统计已在 2.2 全部实现，分别见[基础流程实现说明](09_基础流程实现说明.md)、[管理能力实现说明](10_管理能力实现说明.md)和[跨问卷统计实现说明](11_跨问卷统计实现说明.md)。当前实际契约以运行中的 `/docs` 和[2.2 完整 OpenAPI](附件/openapi-v2.json)为准，本文的草案附件保留为设计记录。

配套[增量 OpenAPI 契约](附件/openapi-v2-draft.json)采用 [OpenAPI 3.1.0](https://spec.openapis.org/oas/v3.1.0.html)，覆盖 26 项新增操作及 7 项需要更新读写契约的既有操作。认证、填写提交、答卷及原整卷统计等其余接口继续参考[第一阶段 API](03_API说明.md)，原 OpenAPI 附件不覆盖为设计稿。

## 1. 通用约定

- 新开发环境基地址为 `http://127.0.0.1:8001`。以下所有路径均需 Bearer 登录，包括 `/api/public/`。
- 沿用 `/api`，不另加路径版本前缀；问卷结构版本由后端确定。新建问卷写结构 v2，前后端需同步更新保存契约。
- 请求使用 JSON、字段名 camelCase；ObjectId 以 24 位十六进制字符串传输，响应统一小写；卷内、选项和规则 ID 沿用现有 `StableId`。
- 请求禁止未声明字段。所有者、创建者、时间、来源结论、版本编号、快照和授权结果由服务端生成。
- 本契约中的全部 17 项管理写操作要求 `Idempotency-Key` 请求头；同一逻辑操作的重试沿用原键和参数，详见第 10.1 节。现有答卷提交继续使用 `submissionKey`。
- 沿用日期、严格数字、去首尾空白、Unicode 码点长度、12 MiB 请求体和 16 MiB 最终文档上限。
- 分页默认 `page=1&pageSize=20`，`page >= 1`、`1 <= pageSize <= 100`；响应为 `{items,total,page,pageSize}`，部分列表另有明确的汇总字段。
- 管理权限不足、路径资源不存在或版本不属于路径题目，统一 `404 NOT_FOUND`。只有已通过相应权限检查后，才返回归档状态、修订号冲突等业务信息。
- 成功响应均为 JSON；删除题库、移出题库也返回 200 JSON，便于沿用现有请求封装的响应解析方式。

### 1.1 修订号的归属

| 请求 | `revision` 的含义 |
|---|---|
| 题目创建版本、恢复、题目/版本归档状态变更、授权、撤权 | 父题目 `questions.revision` |
| 问卷 PATCH、发布、关闭 | `surveys.revision` |
| 题库名称/说明 PATCH、删除题库 | `question_banks.revision` |

`revision` 为当前预期值，范围沿用 `1..9007199254740991`；过期返回 `409 REVISION_CONFLICT`。真实管理变更递增对应修订号。以当前修订号重复设置相同归档或授权状态，返回 200，不递增；旧修订号即使意图相同也返回 409。

源题的独立副本创建、问卷新增引用不接收源题管理修订号：它们固定使用不可变版本，新增其他版本不应使其失败。其权限和归档检查仍在事务内与源题 `guardRevision` 协调。

共享关系自身的 `revision` 和所有 `guardRevision` 均为内部字段，不暴露为客户端管理凭据。题库成员增删不递增公开题库修订号，使用内部协调点与删库操作保持一致性。

## 2. 接口总表

### 2.1 题目、版本和共享：14 项新增操作

下表中的 `{question_id}` 为库级题目 ID，`{version_id}` 为库级版本 ID。

| 方法与路径 | 权限 | 请求或参数 | 成功响应 |
|---|---|---|---|
| `POST /api/questions` | 已登录 | `content` | 201，`{question,version}`，新题 v1 |
| `GET /api/questions` | 本人或当前获共享题目 | `scope`、`archive`、`search`、分页 | 200，题目摘要分页 |
| `GET /api/questions/{question_id}` | 所有者或当前接收者 | 无 | 200，题目详情 |
| `PATCH /api/questions/{question_id}` | 所有者 | `revision,archived` | 200，题目详情 |
| `GET /api/questions/{question_id}/versions` | 所有者或当前接收者 | `archive`、分页 | 200，版本摘要分页，附 `questionRevision` |
| `POST /api/questions/{question_id}/versions` | 所有者 | `revision,baseVersionId,content` | 201，`{question,version}` |
| `GET /api/questions/{question_id}/versions/{version_id}` | 所有者或当前接收者 | 无 | 200，`{questionRevision,version}` |
| `PATCH /api/questions/{question_id}/versions/{version_id}` | 所有者 | `revision,archived` | 200，`{questionRevision,version}` |
| `POST /api/questions/{question_id}/restore` | 所有者 | `revision,sourceVersionId` | 201，`{question,version}` |
| `POST /api/questions/{question_id}/copies` | 当前有权使用该版本者 | `versionId` | 201，新独立题的 `{question,version}` |
| `GET /api/questions/{question_id}/shares` | 所有者 | `state`、分页 | 200，共享关系分页，附 `questionRevision` |
| `POST /api/questions/{question_id}/shares` | 所有者 | `revision,recipientUsername` | 首次 201，已存在/重新授权 200，`{questionRevision,share}` |
| `POST /api/questions/{question_id}/shares/{share_id}/revoke` | 所有者 | `revision` | 200，`{questionRevision,share}` |
| `GET /api/questions/{question_id}/usage` | 所有者 | 分页 | 200，可见问卷明细及其他问卷引用数 |

归档与取消归档使用 `archived:true/false`。版本 PATCH 只允许这一元信息，不允许修改版本内容。取消题目归档不自动取消某个版本的归档；恢复旧版创建新版本也不自动取消父题归档。

### 2.2 个人题库：8 项新增操作

| 方法与路径 | 请求或参数 | 成功响应 |
|---|---|---|
| `POST /api/question-banks` | `name`，可选 `description` | 201，题库详情 |
| `GET /api/question-banks` | 分页 | 200，本人题库分页 |
| `GET /api/question-banks/{bank_id}` | 无 | 200，本人题库详情 |
| `PATCH /api/question-banks/{bank_id}` | `revision`，以及 `name/description` 至少一项 | 200，更新后的题库 |
| `DELETE /api/question-banks/{bank_id}` | 查询参数 `revision`，无请求体 | 200，`{bankId,deleted:true}` |
| `GET /api/question-banks/{bank_id}/items` | 分页 | 200，分类记录分页 |
| `PUT /api/question-banks/{bank_id}/items/{question_id}` | 无请求体 | 新增 201，已存在 200，`{bankId,questionId,created}` |
| `DELETE /api/question-banks/{bank_id}/items/{question_id}` | 无请求体 | 200，`{bankId,questionId,removed}` |

全部先检查题库所有者。题库名称 1～200 字符，说明 0～2000 字符，默认空串，不要求同用户题库名称唯一。删除容器不删除题目、版本、共享关系或问卷引用。

### 2.3 跨问卷统计：4 项新增操作

这些接口以本人问卷为权限入口，不复用原题详情的共享授权依赖。

| 方法与路径 | 作用 |
|---|---|
| `GET /api/question-statistics` | 本人 v2 问卷实际引用过的题目目录，支持 `search` 和分页 |
| `GET /api/question-statistics/{question_id}/versions` | 本人问卷实际引用过的版本分页 |
| `GET /api/question-statistics/{question_id}/versions/{version_id}` | 精确单版本跨本人问卷统计 |
| `GET /api/question-statistics/{question_id}/versions/{version_id}/values` | 文本或数字有效回答原值分页 |

目录返回本人快照中的信息，不返回源题当前最新版、所有者或来源关系。没有本人引用的对象返回 404；已有本人引用但尚无答卷，返回零计数和空统计。目录为空时返回正常空列表。

### 2.4 七项既有操作的契约更新

配套 OpenAPI 包含 `POST/GET /api/surveys`、`GET/PATCH /api/surveys/{survey_id}`、发布、关闭及公开问卷 GET。

问卷管理读响应区分 v1/v2；新建和题目结构写请求改为引用 DTO；公开 GET 使用字段白名单。认证、`start/preview/submit` 的凭据与答案含义、答卷分页及原整卷统计接口继续沿用既有契约。

## 3. 题目内容和读取 DTO

### 3.1 版本内容输入

`content` 不含卷内 ID、必答、顺序或跳转。四题型的选项、校验和容量沿用现有规则；单独保存时先检查内容自身，加入问卷后再结合必答和跳转校验。

```json
{
  "content": {
    "type": "number",
    "title": "你的年龄",
    "description": "请填写周岁",
    "validation": {"integerOnly": true, "min": 0, "max": 150}
  }
}
```

`type/title` 必填；`description` 默认空串，`validation` 按题型补齐默认值；选择题必须有 2～50 个 `{id,label}` 选项。文本/数字题禁止 `options`；未设置的限制省略，不传 `null`。

题目摘要返回 `_id,ownerId,revision,latestVersionId,latestVersion,archivedAt,createdAt,updatedAt,permissions`。`permissions` 为 `{canManage,canUse}`，只是界面提示，写入时仍重新鉴权。`canUse` 表示该题当前至少有一个可选版本。

题目详情在摘要上增加 `origin`。副本来源只返回题目/版本 ID，不展开未经授权的源内容；迁移来源中的旧问卷 ID 和实例 ID，仅向有权访问该旧问卷者返回，其他接收者只看到 `kind:"legacy"`。

`latestVersion` 是最后创建的版本摘要，即使它已归档也不暗中改指向上一版。版本列表通过 `archive` 明确筛选可选版本。

版本详情含 `_id,questionId,versionNo,baseVersionId,operation,content,createdBy,createdAt,archivedAt,permissions`。版本列表摘要也返回 `baseVersionId/operation`，便于直接展示版本来源。内容、编号和来源不能经 PATCH 改写。

### 3.2 列表参数

| 接口 | 参数与默认值 | 顺序 |
|---|---|---|
| 题目列表 | `scope=owned/shared/all`，默认 `owned`；`archive=exclude/include/only`，默认 `exclude`；`search` 最多 200 字符，搜索最后创建版本的题干 | `updatedAt,_id` 倒序 |
| 版本列表 | `archive` 同上 | `versionNo` 倒序 |
| 共享列表 | `state=active/revoked/all`，默认 `all` | `updatedAt,_id` 倒序 |
| 题库列表 | 通用分页 | `updatedAt,_id` 倒序 |
| 题库成员 | 通用分页，包含不可用占位记录 | `createdAt,_id` 倒序 |
| 统计题目目录 | 按本人展示题干字面搜索 | `questionId` 升序 |
| 统计版本目录 | 通用分页 | `versionNo` 倒序 |

## 4. 创建版本、恢复与独立副本

### 4.1 保存修改

```http
POST /api/questions/000000000000000000000101/versions
```

```json
{
  "revision": 3,
  "baseVersionId": "000000000000000000000102",
  "content": {
    "type": "number",
    "title": "你的年龄",
    "description": "请填写周岁",
    "validation": {"integerOnly": true, "min": 0, "max": 120}
  }
}
```

服务端验证来源为同题版本，在同一事务分配下一个序号、插入新版本、更新父题修订号及最新版本指针。`baseVersionId` 可以不是最后创建版本；来源关系与创建序号分别记录。

### 4.2 恢复为新版本

```http
POST /api/questions/000000000000000000000101/restore
```

```json
{"revision": 4, "sourceVersionId": "000000000000000000000102"}
```

只复制指定版本内容，记录 `operation=restore` 及来源版本。请求带 `content` 即 422。所有者可以从保留的历史内容恢复新版本；归档来源不会被原地改写。

“选用历史版本”没有额外恢复接口，直接将旧版本 ID 保存到草稿问卷引用中。

### 4.3 另存为独立题目

```http
POST /api/questions/000000000000000000000101/copies
```

```json
{"versionId": "000000000000000000000102"}
```

源题和源版本须当前可使用。新题所有者取当前登录者，新题首版编号为 1，`operation=copy`、`baseVersionId=null`，跨题来源由服务端生成。请求不能夹带替代内容；需要改编时，先获得独立副本，再为副本保存新版本。

以上三种创建操作统一返回 `{question,version}`。其中 `question.revision` 是后续管理所需值；副本返回的是新题修订号。

## 5. 整题授权与撤权

```http
POST /api/questions/000000000000000000000101/shares
```

```json
{"revision": 5, "recipientUsername": "student_a"}
```

按现有用户名标准化规则精确匹配注册用户，不提供模糊用户目录。授权只接收用户名，不接收 `versionIds`、角色、所有者或“允许修改原题”等额外字段。整题授权含未来版本。

成功响应示意：

```json
{
  "questionRevision": 6,
  "share": {
    "_id": "000000000000000000000301",
    "recipient": {"_id": "000000000000000000000401", "username": "student_a"},
    "grantedAt": "2026-10-22T08:00:00.000Z",
    "revokedAt": null,
    "createdAt": "2026-10-22T08:00:00.000Z",
    "updatedAt": "2026-10-22T08:00:00.000Z"
  }
}
```

撤权调用共享记录下的 `/revoke`，请求仅传父题 `revision`。重新授权复用同一共享记录，更新授权时间、清空撤权时间。撤权不遍历修改问卷、快照、统计或独立副本。

撤权后原题详情和完整版本 API 按当前权限返回 404；已有草稿通过保存的快照继续使用，历史统计走本人问卷入口。

## 6. 问卷保存：引用输入与快照输出分离

### 6.1 创建与 PATCH 输入

创建保留 `title/description/settings/deadlineAt/questions`；题目数组默认空，`settings.anonymous` 仍必填。PATCH 继续要求问卷 `revision` 和至少一个待改字段。

```json
{
  "revision": 7,
  "questions": [
    {
      "id": "q_age",
      "questionId": "000000000000000000000101",
      "versionId": "000000000000000000000102",
      "required": true,
      "jumpRules": []
    }
  ]
}
```

每项只允许 `id/questionId/versionId/required/jumpRules`；前四项必填，跳转默认空数组。传入题干、题型、选项、校验、`versionNo` 或快照内容，即使值与服务器相同，也返回 422。

`jumpRules` 先解析规则结构，再按服务端加载的实际题型和整卷关系校验。替换版本推荐保持实例 `id`，以保留其他题指向它的目标，但本题的条件和全部跳转仍需重新验证；不静默删除失效规则。

### 6.2 管理读取响应中的实例

```json
{
  "id": "q_age",
  "questionId": "000000000000000000000101",
  "versionId": "000000000000000000000102",
  "versionNo": 1,
  "type": "number",
  "title": "你的年龄",
  "description": "请填写周岁",
  "validation": {"integerOnly": true, "min": 0, "max": 150},
  "required": true,
  "jumpRules": []
}
```

读取响应不能原样回传为保存请求。前端必须构造引用写入 DTO；服务端生成或保留可信快照。

### 6.3 撤权后的已有引用

1. 与数据库当前实例的 `(id,questionId,versionId)` 完全相同：保留原快照，允许调整合法卷内设置，不要求当前源题授权。
2. 改实例 ID、改题目、换版本或新增实例：重新检查权限和归档状态。
3. 已删除并保存后重新加入：属于新增使用。旧页面的过期问卷修订号不能复活被删除引用。
4. 同卷重复库级 `questionId`，即使版本不同，也返回 `422 DUPLICATE_QUESTION`。
5. 一次保存中的引用校验和写入同一事务，任一题失败整体不写入。
6. 发布既有草稿使用保存的快照，不因当前撤权或归档而拒绝原引用。

答案和跳转中的 `questionId` 仍是卷内 `id`，不能改传库级 ObjectId。原整卷统计的 `?questionId=q_age` 也保持这个含义。

## 7. 题库成员与不可用占位

新增分类只要求当前有权读取该题，不因分类形成使用授权；归档题可以整理，但不能新增选用。已存在的分类重复 PUT 返回 `created:false`，不重新授予权限。

撤权后分类可以保留，成员列表按真实分类记录分页，`total` 包含不可用项。不可用项仅返回：

```json
{"questionId": "000000000000000000000101", "available": false}
```

可读项返回 `{questionId,available:true,question:<题目摘要>}`。不可用项不补充题干、作者、版本或撤权原因。移出自己的分类不要求当前仍有源题权限。

## 8. 引用情况查询

```json
{
  "questionId": "000000000000000000000101",
  "totalSurveyCount": 8,
  "visibleSurveyCount": 3,
  "otherSurveyCount": 5,
  "items": [
    {
      "surveyId": "000000000000000000000201",
      "title": "课程调查",
      "status": "published",
      "instanceId": "q_age",
      "versionId": "000000000000000000000102",
      "versionNo": 1
    }
  ],
  "total": 3,
  "page": 1,
  "pageSize": 20
}
```

计数按不同问卷，覆盖草稿、已发布和已关闭状态。`total` 为可见明细总数，不是全站引用数；汇总计数不受分页影响，满足 `totalSurveyCount = visibleSurveyCount + otherSurveyCount`。

其他用户的问卷只贡献总数，不返回 ID、名称、答卷数或版本明细。独立副本不算原题直接引用；没有库级身份的未迁移 v1 不参与计数。

## 9. 跨问卷统计契约

### 9.1 统计目录与可用版本

题目目录按本人问卷当前保存的引用和快照构建，按题目身份去重，元素为：

```json
{
  "questionId": "000000000000000000000101",
  "title": "你的年龄",
  "displayVersionId": "000000000000000000000102",
  "displayVersionNo": 1,
  "surveyCount": 2,
  "usedVersionCount": 1
}
```

展示题干取本人实际使用过的最高序号版本，不等于源题当前最新版。版本目录只列本人实际引用过的版本，元素包含 `questionId/versionId/versionNo/title/type/surveyCount`，不从源题完整历史补齐。

### 9.2 精确版本统计

多选统计示意：

```json
{
  "questionId": "000000000000000000000105",
  "versionId": "000000000000000000000106",
  "versionNo": 1,
  "title": "喜欢哪些环节？",
  "type": "multiple",
  "surveyCount": 2,
  "totalResponses": 12,
  "answeredCount": 10,
  "unansweredCount": 2,
  "options": [
    {"optionId": "lab", "label": "实验", "count": 8, "ratio": 0.8},
    {"optionId": "discussion", "label": "讨论", "count": 6, "ratio": 0.6}
  ]
}
```

- `surveyCount` 是本人包含该精确版本的问卷数量，包含无答卷草稿。
- `totalResponses` 是这些问卷的成功答卷份数；`answeredCount` 排除空值和跳过。
- `unansweredCount = totalResponses - answeredCount`，合并留空和跳过，不称为独立人数。
- `ratio` 为 0～1 的小数，前端转换百分比；分母是 `answeredCount`，多选各比例之和可大于 1。零有效回答时每个比例为 `null`。
- 数字题返回 `minimum/maximum/average`；零有效回答时均为 `null`。
- 文本题返回相同计数，回答原值通过 `/values` 分页取得。

无本人引用的题目或版本返回 404，即使当前拥有原题授权。撤权或归档后，只要本人引用仍在，就可以查询其历史统计。内容与选项解释来自本人快照。

### 9.3 原值分页

`/values` 适用于文本和数字题，返回 `{questionId,versionId,type,items:[{value}],total,page,pageSize}`。只含有效回答，不返回账号、答卷 ID 或提交 key；排序使用提交时间、答卷 ID 倒序，分页不影响总数或聚合结果。

选择题调用该原值入口返回 `409 STATISTIC_VALUES_UNSUPPORTED`，使用选项统计即可。保留原整卷统计对文本/数字单题的既有分页契约。

## 10. 错误码、并发与重试

沿用 `{"error":{"code":"...","message":"...","details":...}}`，不回显密码、token、完整答案或其他用户数据。

| 状态 / 业务码 | 场景 |
|---|---|
| 401 / 既有认证错误码 | 未登录或登录凭据无效 |
| 404 / `NOT_FOUND` | 不存在、无相应权限、路径版本不属于题目、无本人统计引用 |
| 409 / `REVISION_CONFLICT` | 管理修订号或条件更新冲突 |
| 409 / `IDEMPOTENCY_KEY_REUSED` | 同一用户已使用的键被用于不同操作、目标或规范化参数 |
| 409 / `IDEMPOTENCY_IN_PROGRESS` | 同键请求仍在执行或确认，附 `Retry-After`，沿用原键稍后重试 |
| 409 / `QUESTION_ARCHIVED` | 对已归档且当前可读题目尝试新增使用 |
| 409 / `VERSION_ARCHIVED` | 对已归档且当前可读版本尝试新增使用 |
| 409 / `LEGACY_SURVEY_REQUIRES_MIGRATION` | 对 v1 问卷提交新版题目结构修改 |
| 409 / `STATISTIC_VALUES_UNSUPPORTED` | 对选择题请求原值分页 |
| 409 / 既有问卷状态错误码 | 发布冻结、关闭只读或非法状态操作 |
| 413 / 既有大小错误码 | 请求体或最终文档过大 |
| 422 / `INVALID_REQUEST` | 字段、类型、参数错误；夹带快照、修改版本内容、恢复请求夹带内容 |
| 422 / `DUPLICATE_QUESTION` | 同卷重复题目身份，`details` 可含 `libraryQuestionId,instanceIds` |
| 422 / `DUPLICATE_INSTANCE` | 同一问卷内重复卷内题目 ID |
| 422 / `SHARE_RECIPIENT_NOT_FOUND` | 通过原题所有者鉴权后，精确用户名没有对应已注册用户 |
| 422 / `SELF_SHARE_NOT_ALLOWED` | 试图向自己共享原题 |
| 422 / `VALIDATION_ERROR`、`EMPTY_PATCH` | 题型关联、跳转、字段关系或空更新不合法 |
| 503 / `DATABASE_ERROR` | 数据库失败或可重试事务冲突在限制内未完成 |
| 503 / `IDEMPOTENCY_RESULT_UNKNOWN` | 提交结果暂时无法确认，不表示已回滚；沿用同键确认 |
| 503 / `IDEMPOTENCY_RESULT_UNAVAILABLE` | 已有成功回执但响应存储暂不可读；保留去重记录，禁止重做业务 |

404 可附请求中已有的 `instanceId` 以定位保存失败项，但不附隐藏源题状态。新接口不以 403 向共享接收者揭示所有者管理资源；原提交凭据绑定不符的 403 保持原契约。

首次执行业务的写冲突重试须重新读取权限，不能重用事务外的授权结果。明确中止的事务不留下部分业务写入；若提交结果不明，不能仅因 HTTP 请求失败就宣称事务已回滚。

### 10.1 管理请求幂等契约

事务保证一次操作内部完整，`revision` 防止过期更新；两者均不能单独识别多个 HTTP 请求是否属于同一次用户操作。使用持久化成功回执补齐响应丢失、重复点击与并发重试。

#### 适用范围与请求头

全部 17 项管理写操作统一要求幂等键：10 项 POST、4 项 PATCH、2 项 DELETE 和 1 项 PUT，包括建题、建版本、恢复、另存、建题库、建问卷，以及其他管理变更。GET、认证及填写入口不使用这一协议；答卷提交保留原协议。

```http
Idempotency-Key: 89f2d440-5d6e-4d77-a2c3-8a12d3974809
```

键为客户端生成的小写 UUID v4，不含用户或题目内容。同一用户的键跨管理写接口唯一；服务端以 `(actorId,key)` 唯一索引隔离不同用户。

以下行为严格区分：

| 请求情况 | 结果 |
|---|---|
| 首次有效操作 | 原成功状态码及响应，`Idempotency-Replayed:false` |
| 已成功的同键、同操作、同目标、同参数 | 返回第一次成功状态码和原 JSON 响应，`Idempotency-Replayed:true`，不再写业务数据 |
| 已使用同键但操作、目标或参数不同 | 409 `IDEMPOTENCY_KEY_REUSED` |
| 同键请求正在竞争，暂时无法获得完成结果 | 409 `IDEMPOTENCY_IN_PROGRESS`，`Retry-After:1`，客户端沿用同键重试 |
| 提交结果不明 | 503 `IDEMPOTENCY_RESULT_UNKNOWN`，客户端沿用同键确认 |
| 不同键，即使内容完全一样 | 视为不同逻辑操作；建题可能分别创建，不能靠内容相同去重 |
| 缺少或不符合格式的键 | 422 `INVALID_REQUEST` |

参数摘要使用纯输入规范化后的 DTO，包括默认值、规范化日期/ObjectId、HTTP 操作及目标和原始预期 `revision`；JSON 对象键顺序不影响摘要。保持规范化算法版本，不读取“当前最新版本”来替代请求参数。查询到旧回执时使用其 `canonicalVersion` 对应的输入约定和算法，升级后继续支持旧摘要，不能用最新默认值误判合法重放。结构非法的请求先返回 422；明确失败并回滚的请求不缓存为成功。

#### 回执与业务写入同一事务

1. 登录鉴权、校验纯请求结构后，先查询本人同键成功回执；成功重放不检查当前 revision 或重新发起原操作。
2. 没有成功回执则进入事务，先占用键，再检查业务权限、revision 和状态，执行业务写入，保存成功响应与回执，一并提交。
3. 并发同键通过唯一索引竞争；重复键或写冲突后，退出旧事务并重新查询回执，不继续使用旧快照创建另一份资源。
4. 不在独立缓存中先记录“成功”再写数据库，也不在业务提交后另开事务补回执。进程重启不丢失已提交回执。
5. 驱动提交确认仍不明时，未读到回执不能证明失败；始终保留原键。回执与响应分片无短 TTL，不因记录过期重新执行旧请求。

业务与回执事务统一使用 primary、`readConcern:snapshot` 和 `writeConcern:majority`，配合部署的日志持久化设置；完成结果确认使用 primary/majority 读取，不能从可能滞后的副本读取后判断“没有执行过”。

恢复示例：`restore(v1,revision=3,key=K)` 创建 v4 并将父题修订号变为 4，同时提交 `K → v4` 回执。即使响应丢失，原请求再次到达仍返回第一次的 v4；不会生成 v5，也不会先因 revision 已变化返回冲突。把 revision 改为 4 却继续使用 K，则是异参复用，应返回 409。

回执只对原登录主体重放。另存成功后原题撤权，重放的是已创建的本人副本，不重新检查源题使用权，也不展开源题新数据。历史成功确认不表示资源仍是当前状态：资源可能后来修改、归档或删除；重放不会复活它。前端收到重放标记后，需要 GET 当前资源再继续管理，不能把缓存的 revision 或 permissions 当作当前值。

回执以内联或分片保存原响应，避免接近文档大小上限的问卷响应撑破单个回执文档；具体存储见[模型中的回执设计](07_新版数据模型设计.md)。响应缺失或校验失败时保留成功去重记录，返回不可读取错误，不能重新执行业务修复响应。

#### 前端操作身份

- 在同一逻辑操作首次发送前生成键；重复点击共用该键。按钮禁用仅改善体验，服务端仍须保证幂等。
- 超时、断网、可重试错误和页面刷新后，恢复同一操作的键及原参数，不能每次 fetch 或每次点击重新生成键。
- 按登录主体和编辑操作保存待确认信息；结果不明时冻结原参数，不自动刷新 revision 后重新提交。修改输入或明确发起另一笔操作时使用新键，先妥善确认原操作结果。
- 已完成操作的按钮不能在未创建新意图时自动换键再次提交。只有用户明确“再建一道题”或“再次恢复”，才产生新逻辑操作。

这里借鉴的是[幂等请求识别与结果重放模式](https://docs.stripe.com/api/idempotent_requests)，本项目采用自己的持久化回执和保留策略，不采用删除短期键后重新执行旧操作的策略。

## 11. 兼容与公开输出

| 既有能力 | 新版处理 |
|---|---|
| 新建问卷 | 只接受引用数组并写 v2；旧的完整题目写法返回 422 |
| v1 问卷读取、原填写及原统计 | 保留 |
| v1 元信息 PATCH、按状态发布/关闭 | 保留原状态规则 |
| v1 题目结构修改 | 先通过显式迁移工具升级，不提供网页迁移写接口 |
| v2 管理读取 | 返回库级引用与可信快照 |
| 公开填写 GET | 无论 v1/v2，使用下述白名单 |
| 预览、提交和既有单卷统计的 `questionId` | 继续指卷内 ID |

公开问卷顶层仅返回现有 `_id/publicId/title/description/status/settings/deadlineAt/questions/canSubmit`。每题仅返回 `id/type/title/description/required/validation`，选择题另有 `options`。

公开 GET 不返回库级 `questionId/versionId/versionNo`、所有者、来源、能力、内部修订号或跳转规则。必须替换当前“仅排除 jumpRules”的实现，避免新增字段随对象自动透出。

实现时同步扩展 CORS 方法支持 `PUT/DELETE`、请求头允许 `Idempotency-Key`，并向前端暴露 `Idempotency-Replayed/Retry-After` 响应头。前端请求封装接收操作已有的键，不在每次 fetch 内创建键。新增响应需声明类型模型，避免重复现有部分 OpenAPI 响应为空 schema 的问题。保留原接口附件作为第一阶段记录，新版实现后再从应用导出正式 OpenAPI，并与本设计对照。

## 12. 实施与契约验收顺序

1. 内容、引用和读取 DTO；题目/版本创建；问卷引用保存及原填写回归。
2. 历史版本、恢复、归档；整题共享、另存、撤权与既有草稿保留。
3. 题库分类、删除一致性、引用数量与可见性。
4. 本人统计目录、单版本聚合、原值分页及撤权后的历史读取。

重点验收：请求夹带快照被拒绝；恢复不接受内容；共享不能修改原题；整题新增版本可见而问卷不追新；撤权与新增引用竞争结果一致；已有引用可发布；同卷同题跨版本仍拒绝；副本和恢复版本分别统计；其他用户问卷不泄露；零分母和无样本正确；v1 路径含义不变；公开输出没有库级内部字段。

幂等专项验收：同键并发仅一次提交；成功提交后主动断开响应再重放；恢复重放不先检查新 revision；同键异参拒绝；事务中断后不残留成功回执或分片；副本成功后源题撤权仍能确认副本；刷新保留原键；没有 TTL 导致的过期重做；大问卷响应分片重放完整；回执历史状态不覆盖当前状态。
